# DSH APP — brand plugin suite

The suite is eighteen dsh plugins that layer on top of upstream dsh **without
forking it**. This is what keeps the desktop app updateable: when upstream dsh
releases a new version, the shell swaps the kernel and these plugins keep
working.

## Packages

| Package | Side | Role |
|---|---|---|
| `plugin-brand` | host | **partial scaffold** — settings namespace and app-info service are declared but not wired yet; the desktop bridge's shell side (action route + connection routes) IS wired, while the plugin-side facades (settings page rows, appInfo service) are not |
| `plugin-client-ui` | client | brand theme, brand Models settings section, Diagnostics page (desktop-feature status, kernel log tail, diagnostics export, office-components row) |
| `plugin-sidebar` | dual | Git panel as a native conversation-view tab (the file tree was retired: upstream ships file management natively) |
| `plugin-swarm` | dual | batch parallel subagent orchestration (`swarm` tool + `/swarm` command), adaptive concurrency, per-item retry, kernel-capacity backpressure (a rejection at the shared live-child limit shrinks the pool and re-queues the item instead of failing it) |
| `plugin-usage` | dual | usage capture over session logs + settings-page balance card, heatmap, daily trend chart |
| `plugin-archives` | dual | session archive manager (list/delete routes + settings-page section grouped by project) |
| `plugin-memory` | dual | cross-session memory (project-scoped card files injected per prompt, memory_save/recall/forget tools the model calls itself, background curator over existing cards plus a per-project "curate now" button, settings page with per-entry pin/delete; the global scope was retired and its cards migrated into a `legacy-global` project) |
| `plugin-mcp` | dual | external MCP server manager: settings-page CRUD, dynamic mount, tools registered as native `mcp__<server>__<tool>` |
| `plugin-hooks` | dual | external hooks bridge: settings-page CRUD over Claude Code / Codex `hooks.json`, mounted as live hook instances |
| `plugin-ppt` | dual | editable PPTX generation: the model authors a local PPTD project (`.pptd` manifest + `.page` YAML) against bundled layout templates via `ppt_list_templates`/`ppt_get_template_reference`/`ppt_get_template_pages`/`pptd_write_file`/`pptd_list_files`/`pptd_read_file`/`pptd_check`/`pptd_render` (read-only check locates text overflow/occlusion per file-page-elementId before export), a guiding skill installed into `$DSH_HOME/skills`, and the PPT mode capsule in the **office-suite capsule bar** — the row of format capsules injected after the composer card (container class `dshOfficeBar`, one host per format as `[data-office-format]`, container reused and hosts ordered/deduplicated by that attribute so later Word/Excel/PDF plugins join the same row; see `plugins/plugin-ppt/src/client/office-bar.ts`). The capsule toggles the mode and opens a real cover-preview template panel behind its ▾ dropdown; a pick made before any session exists is parked and applied to the session once it starts |
| `plugin-market` | dual | plugin marketplace: sidebar footer entry + drawer panel over user-configurable catalog sources, install/uninstall through the kernel CLI with registry-only validation, and every install minted as a ONE-SHOT intent bound to a catalog row (`src/install-intent.ts`) — the panel submits a row id and then the token — a package name, version, force flag, repo key or git target in the install body is ignored, which removes exact-version pinning and arbitrary git targets (the catalog SOURCE list stays user-editable, so a row can still come from a source the user added) — and a replayed, expired or other-profile token is refused; plus the model-facing bridge (`src/bridge.ts`, `src/bridge-install.ts`): `market_search` answers "is there a skill/plugin for X" from the real skill and plugin catalogs, and `market_install_skill` / `market_install_plugin` / `market_uninstall_skill` perform the install once the user has chosen — over the same executors and the same serialized queue the panel's click uses. A plugin install only ever ADDS an uninstalled name: a name already present (a local/Git development copy included) is refused and named, because replacing an existing install is the panel's own confirmed action |
| `plugin-presets` | dual | portable preset packages: settings-page export of a preset directory as a shareable `.dshpreset` archive and import with kernel-roster-aligned name/path/size fencing |
| `plugin-doc` | dual | Word documents: `doc_write`/`doc_check`/`doc_render` tools over a validated JSON document project, rendered to an editable `.docx`; Word capsule in the shared office bar |
| `plugin-sheet` | dual | Excel workbooks: `sheet_write`/`sheet_check`/`sheet_render` tools over a validated JSON workbook project, rendered to an editable `.xlsx` with formulas; Excel capsule in the shared office bar |
| `plugin-pdf` | dual | PDF mode: `pdf_read` extracts text/metadata from workspace PDFs for the agent, `pdf_write`/`pdf_check`/`pdf_render` produce a paginated, rule-checked PDF with an embedded CJK font subset, and `office_to_pdf` converts an existing `.doc/.docx/.xls/.xlsx/.ppt/.pptx` into a PDF through the application's own on-demand LibreOffice engine (`ctx.officeToPdf`, the same one the document preview uses); PDF capsule in the shared office bar |
| `plugin-websearch` | dual | web search manager: registers ONE `ctx.web` search provider (`dsh-app`) whose engine chain (anysearch / bing / parallel / exa / searxng, in that preference order) falls back automatically, plus ONE `ctx.web` fetch provider (`dsh-app-fetch`) that serves `web_fetch` with the host's contract and a fake-IP-safe resolution layer (proxy route when the shell injected one, system resolver when clean, DNS-over-HTTPS when a canary probes the network as poisoned), plus a settings-page section that orders engines, stores keys and switches between the brand chain and the upstream DeepSeek provider — each side showing its own availability so the switch never silently fails. The model-facing `web_search` / `web_fetch` tools stay upstream's — only the providers behind them change. Replaces the hand-written `dsh-free-search` + exa/parallel MCP overlay rows |
| `plugin-rewind` | dual | message recall + file revert: `/rewind <n>` cuts the model-visible surface back to before a chosen user message through the kernel's own surface-replacement mechanism (`session.append('user/message', …, { surfaceOp: { op: 'replace', … }, sourceEventSeqs: … })` with an empty-content placeholder carrying this plugin's source kind; `system/message` is NOT usable here — the persistence validator requires a system message to match the currently open turn/step and a recall runs while the agent is idle, so that shape writes fine and then makes the log unloadable), hides the affected turns in the chat UI via `data-chat-turn`, and returns the recalled text to the composer through `inputActions.setDraft`. The composer face is read from the MATERIALIZED `uiSession` binding (`uiSession.bindingSource`), never from `sessions.binding(id)` — the raw binding carries no props, and reading `props.inputActions` off it fails silently. Entry points: a hover icon under each user message (a `priority: -1` wrapper around the built-in `user` chat-node renderer — safe only because that renderer calls `renderSlot` zero times) and the `/rewind` command (bare = picker, `/rewind <n>` = direct). A typed `/rewind` is observed through the session's append event feed so both entry points prefill alike. A QUARANTINE MANAGER tab in the maintenance settings section lists every displaced file with its origin path and reason (replaced / created), and discards items individually or a whole session to reclaim disk — per-item confirmed, because the safety copy is the only copy. It reads two host routes (GET /api/plugins/dsh-app/plugin-rewind/quarantine and POST …/quarantine/purge) that take session and slot NAMES, never paths: the handler derives the root from $DSH_HOME and refuses a segment holding .., a separator, a drive prefix or a NUL, so a purge cannot leave the quarantine. A CONFIRMATION STEP: clicking the icon asks the host what a recall WOULD do (`/rewind plan <n>`, a separate verb that cannot change anything) and shows a modal listing every file with its action (restore / move away), an expandable before/after diff, and an explicit count of what cannot be restored; the recall runs only on confirm. FILE REVERT: the two pre-write waterfalls (`fs/write-intent`, `fs/edit-intent`) are hooked with `{ prepend: true }` and MUST forward `next()` — the kernel's own `fs-observation-policy` listener never forwards, so a normally-registered listener would never run, silently. Coverage is only `write`/`edit`/`str_replace_editor` (22.9% of measured tool calls: the hooks those tools dispatch); a file a shell command created, rewrote or deleted (31.4%) is listed as unrestorable, never silently skipped. NOTHING IS DELETED — displaced content moves into `$DSH_HOME/storages/dsh-app-plugin-rewind/quarantine/`, so the recall itself stays reversible. Only this plugin's own replacements hide turns, and only the FIRST prompt of a turn is a recall point (a steering message sharing the prompt shape is not). A recall always cuts at a turn head and is refused while a turn is running, with the reason shown beside the message; the log is append-only |
| `plugin-effort` | client | reasoning-effort track on the **official model menu's 推理等级 row**. That menu contributes no slot of its own, so the browser half injects ONE container beside the row and turns that row into a capsule (geometry, ring and the level's own colour written as inline styles, every one of them snapshotted before the first write and restored on unmount); the SAME level colour is written onto the composer capsule's own level text — the kernel's `… Max` beside the model name, marked `data-dshAppEffort` and weighted by this plugin's stylesheet, never retyped — so the two readings of one level cannot drift apart. The row is identified from the kernel's OWN dictionary (`ctx.locale.bind('model')('menu.effort')`, which follows the active locale) plus a structural check, and the composer's level span by the trigger's child shape, never by a hashed class; when a shape does not match it writes nothing, because a missing track costs nothing and a track on the wrong row is a wrong control. Levels come from the current model's own advertised list and a position is resolved **by id, never by index** — an id the list does not carry falls back to the model's default and then reports itself as unknown rather than being drawn at the left end. The transient values (drag draft, pending commit, error) are keyed by `provider/model/level-ids`, so a model switch drops them instead of reusing an index that meant something else. Growing the card re-triggers the official menu's own placement (a window resize is the only signal its effect listens for), which is what keeps it from overlapping the composer. The value is written through `ctx.modelDirectories` — the same per-session directory the official seat and `/model` popup read — so all three surfaces stay one state |

The roster lives in the places listed below that must stay in sync — `SUITE_PLUGIN_DIRS`
(src/main/brand-suite.ts), the overlay rows in `dsh-app.patch.yml`,
`SUITE_PLUGINS` in scripts/kernel-line.mjs, the pre-build loop in
`.github/workflows/release.yml`, and scripts/smoke-suite.mjs.

## Integration into the kernel runtime

The runtime artifact build (scripts/build-runtime.mjs) adds the suite via
`file:` references into the runtime profile's package.json, so a published
kernel contains dsh + the suite in one immutable directory. Once the suite is
published to npm, switch those references to version ranges.

The loader overlay (`dsh-app.patch.yml`) is copied into userData at server
start and passed to `dsh web --patch ...`; it inserts all eighteen suite entries
after every bundle layer and the profile's own patch (last write wins).
